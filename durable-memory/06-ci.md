# CI: GitHub Actions

`.github/workflows/ci.yml`, modelled on lmhtml's: a 5-platform matrix that
fetches the pinned gnuplot, applies `patches/`, builds, and runs the full
`test.sh`; plus a release job on `v*` tags.

## Jobs

| name | runner | notes |
| --- | --- | --- |
| linux-x64 | ubuntu-24.04 | `-static`, `ldd` check |
| linux-arm64 | ubuntu-24.04-arm | same |
| macos-arm64 | macos-15 | system libraries only (`otool -L`) |
| macos-x64 | macos-15-intel | same |
| windows-x64 | windows-2022 | MinGW g++ via choco, `-static`, `objdump -p` import check |

All run `scripts/sync-gnuplot.sh` (clone of github.com/gnuplot/gnuplot at the
pinned commit, shallow) and `scripts/sync-sdk.sh --verify`, install
`@lmctl-ai/lmctl@0.2.369` for the `lmscript` compiler, then `./test.sh`
(18 checks, 28 examples, 75 images) and upload `dist/`: the binary
(`lmplot-<platform>[.exe]`), `LICENSE`, `THIRD_PARTY_NOTICES` and
`lmplot-gnuplot-patches.tar.gz` (gnuplot's license wants the modifications
shipped with binaries).

`workflow_dispatch` with `only: <platform>` runs a single job. Path filters
skip docs-only pushes; tag pushes always build.

## Release

Pushing a tag `vX.Y.Z` runs the matrix, then the `release` job downloads all
artifacts, checks that `dist/lmplot-linux-x64 --version` is exactly
`lmplot X.Y.Z` (bump `project(lmplot VERSION ...)` first; lmscript's
`install=` compares that string with the tag), and creates or updates the
GitHub release with `gh release create/upload --clobber`. Only that job has
`contents: write`.

## Notes

- The first run of the matrix was green on all five platforms (the Windows
  port described in `02-gnuplot-embedding.md` had been checked by cross
  compiling with zig first, which is the cheap way to find compile errors).
- Lessons carried over from lmhtml and applied up front: `.gitattributes`
  `* text=auto eol=lf` (the sdk pin is a sha256), no empty-array expansion
  under `set -u` (macOS bash 3.2), CMake `"Clang"` also matches AppleClang so
  `-static` is excluded on Apple, binary stdout on Windows, `pwd -W` native
  paths for tools that cannot read git-bash paths.
- Another trap that was found locally, not on CI: anything in the tests that
  triggers gnuplot's built-in pager (`set terminal`) must not leave stdin
  open.

## v0.1.1 release candidate

The patch candidate includes the reviewed numeric/datablock/output fixes, the Arev font
notice, the committed showcase repairs, and the Windows dry-run null-sink fix through
`LMPLOT_WINDOWS` (gnuplot hides `_WIN32`). An isolated checkout with the pinned gnuplot
commit and eight patches passed all 27 checks, including 109 byte-identical images on
rerun, combo and video pipelines, image input, memory limits and dry-run behavior.
The build under test stays ahead of cached renderer binaries on PATH.
